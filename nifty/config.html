Known Limitations

Real constraints — not edge cases, actual daily operating realities.

1. DAILY TOKEN RENEWAL — MANUAL, NO AUTOMATION
   Zerodha access tokens expire at 7:30 AM daily.
   Renewal requires a human to log into kite.zerodha.com and paste the token.
   Miss the window → that day is lost. No recovery.

2. NO BACKTEST ENGINE
   All validation is forward DRY RUN only.
   Hit rate, expectancy, max drawdown — unknown without months of live data.
   You cannot know if the strategy has edge without running it.

3. SLIPPAGE NOT MODELED IN DRY RUN
   DRY RUN uses signal price as fill price with 0 slippage.
   Live options spreads: ₹2–5+ on ATM strikes. On 65 lots that is ₹130–325 per entry.
   At ₹150 entry price, a ₹3 spread = 2% cost on entry alone.
   Real P&L will be worse than DRY RUN shows.

4. REGIME FILTER IS A HEURISTIC
   0.8% prev-day range filter removes low-volatility days.
   But some low-range days gap on news. Some high-range days are pure chop.
   Filter improves average — it is not a precise signal.

5. ORB FORCE EXIT AT 10:50 CAPS WINNERS
   ORB positions moving in the right direction are hard-exited at 10:50.
   Design choice (capital handoff to Breakout), but it limits ORB upside.

6. MR ENTRY HAS NO CANDLE CONFIRMATION
   MR enters as soon as breakout_seen + spot reverted.
   Does not wait for a close back through the level on 5-min candle.
   Some MR entries are early — spot reverting again after entry is possible.

7. NO VIX OR OPTIONS GREEKS AWARENESS
   India VIX below 12 → options cheap, theta burn fast, moves small.
   India VIX above 20 → options expensive, slippage severe.
   Neither handled. A VIX-based skip filter is phase 2.

8. NSE HOLIDAYS NOT AUTO-DETECTED
   Cron runs Mon–Fri. On exchange holidays the bot starts and polls with errors.
   is_market_open() partially handles this via API response, but not reliably.

9. SINGLE SERVER, NO FAILOVER
   OCI free-tier instance. If it reboots, all instances stop.
   No automatic restart of trading instances on reboot (only telegram_bot restarts).
   Manual intervention required after any server restart during market hours.

Failure Modes

What breaks, how likely, and what protects against it.

# ─── FAILURES THAT CAUSE MONEY LOSS ────────────────────────────────

SCENARIO                        PROBABILITY   MITIGATION
────────────────────────────────────────────────────────────────────
API timeout during SL exit      Medium        force_exit_until_closed() retry loop
Duplicate entry (race condition) Low (fixed)   entry lock + entry_in_progress flag
State lost on restart           Low (fixed)   atomic writes + startup reconciliation
Wrong OHLC levels               Low           Kite API cache, dashboard PDH/PDL visible
Fake breakout (spike & reverse) Medium        is_fake_breakout() pre-entry check
Low-range filter miss           Medium        0.8% threshold, tunable in .env
MR early entry (no confirmation) Medium       breakout_seen 30-min window helps

# ─── FAILURES THAT STOP THE SYSTEM ─────────────────────────────────

SCENARIO                        PROBABILITY   MITIGATION
────────────────────────────────────────────────────────────────────
Process crash (unhandled exc)   Low           broad try/except, Telegram alert, /revive
Token expired mid-session       Very Low      tokens valid until midnight, 9:15 check
CF Worker fails / token not captured Very Low  manual /token fallback via Telegram
Server reboot                   Very Low      @reboot for telegram_bot, manual for trading
Kite rate limit                 Medium        LTP cache (5s TTL), exponential backoff
Screen session detached        Low           screen -r bot_instance_N to reattach

# ─── EMERGENCY ACTIONS ───────────────────────────────────────────────

/panic           → kills all instances, force exits all positions
/squareoff N     → closes position for instance N only
Manual fallback  → log in to kite.zerodha.com and close manually
Kill safety net  → cron at 20:00 pkills all remaining processes

Success Probability — Honest Assessment

Real math, not marketing. Read before going fully live.

# ─── BREAKEVEN MATH ─────────────────────────────────────────────────

Expected Value = (hit_rate × avg_win) − ((1 − hit_rate) × avg_loss)

With current config (50% target, 25% SL, 65 lots, ~₹150 entry):
avg_win     ≈ ₹3,750   (50% gain × ₹150 entry × 65 lots / 2 approx)
avg_loss    ≈ ₹1,875   (25% SL × ₹150 × 65 lots / 2 approx)

Breakeven hit rate = 1875 / (3750 + 1875) = ~33%

→ Win more than 1 in 3 trades → theoretically profitable.
→ Actual hit rate unknown. Need 30+ live trades to measure.

# ─── MARKET REGIME REALITY ──────────────────────────────────────────

Indian markets (rough historical distribution):
  Strong trend days  ~30–35%   Breakout ✅  ORB ✅  MR ❌
  Range / chop days  ~35–40%   All strategies suffer
  Reversal days      ~25–30%   MR ✅  Breakout ❌  ORB ❌

After regime filter (0.8% range threshold):
  ~3–5 low-range days filtered per month
  You still trade ~60–70% of days — cannot avoid reversals

# ─── REALISTIC P&L AT ₹50K CAPITAL ─────────────────────────────────

Trading days / month   ~18–20
After filter           ~13–17 days traded
Expected hit rate      30–40%

Optimistic month    Win days: ~6 × ₹3,000 = +₹18,000
                    Loss days: ~10 × ₹1,800 = −₹18,000
                    Net: ₹0 to +₹5,000  (0–10% gross)

Realistic month     Net: −₹1,000 to +₹3,000  (−2% to +6% gross)
                    After brokerage + STT + GST: tighter

Pessimistic month   Extended chop / reversal regime
                    Net: −₹5,000 to −₹8,000  (−10% to −16%)
